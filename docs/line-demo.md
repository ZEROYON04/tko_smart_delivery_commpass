# LINE連携デモガイド

この文書は、スマ配（スマート配送）のLINE連携をチーム内で再現し、ハッカソンでデモするための手順です。配送先・受取人・経路には必ずダミーデータを使用してください。

## デモで伝えるストーリー

従来の時間帯指定は枠が広く、受取人に急な予定が入ると、ドライバーは訪問後に初めて不在を知ります。本デモでは次の2段階で、訪問前に受取人の状況を共有します。

1. 当日朝：お届け予定と時間帯をLINEで知らせ、すでに受け取れない人から早めに連絡してもらう
2. 配達直前：あと何件・約何分かを知らせ、在宅または10分・30分の短時間不在を共有してもらう

受取人は専用アプリをインストールせず、初回のLINE連携だけで利用できます。

## 実装済みの範囲

- お客様コードを使った初回1回のLINE連携
- 同じ受取人アカウントに追加された荷物への自動紐付け
- 一般的な配送時間帯の表示
  - 午前中（8:00〜12:00）
  - 12:00〜14:00
  - 14:00〜16:00
  - 16:00〜18:00
  - 18:00〜20:00
  - 19:00〜21:00
- 朝の当日通知と二重送信防止
- 「今日は受け取れない」のLINE回答とドライバー画面への反映
- 配達直前の「あと何件・約何分」通知
- 「在宅しています」「10分不在」「30分不在」のLINE回答
- Supabase Realtimeによるドライバー画面への反映
- 受取人画面を開く署名付きURL（発行から36時間有効）

朝通知と配達直前通知は、現時点ではデモの再現性を優先してドライバー画面のボタンから実行します。自動実行する場合は、朝通知APIをEventBridge Schedulerなどから呼び出します。

## 必要なもの

- Node.js 24.18.1以上
- pnpm 11.9.0以上
- Docker Desktop
- LINE公式アカウントとMessaging APIチャネル
- `cloudflared`（スマートフォンのLINEからローカル環境へ接続するデモ時）

## 環境変数

`.env.template` を `.env` にコピーし、Supabaseの値に加えて次を設定します。

```env
LINE_CHANNEL_SECRET=<Messaging APIのチャネルシークレット>
LINE_CHANNEL_ACCESS_TOKEN=<チャネルアクセストークン>

# cloudflaredが発行したURL。末尾の / は付けない
LINE_PUBLIC_SITE_URL=https://example.trycloudflare.com

# 例: openssl rand -hex 32 で作成する。外部へ共有しない
RECIPIENT_LINK_SECRET=<受取人リンク署名専用のランダム文字列>

# ダミーデータを使うデモ時だけtrue
EXPOSE_RECIPIENT_PAGES=true
```

`.env` はGitへコミットしないでください。チャネルアクセストークン、チャネルシークレット、署名用シークレット、LINEユーザーIDを画面共有や発表資料へ載せないでください。

## 起動手順

### 1. DBを起動・初期化

```bash
fnm use 24.18.1
pnpm install
pnpm exec supabase start
pnpm exec supabase db reset
```

`db reset` を行うとLINE連携と通知済み状態も消去されます。デモ直前の初期化後に、後述の初回連携をもう一度行ってください。

### 2. アプリを起動

```bash
pnpm dev --hostname 127.0.0.1 --port 3001
```

ドライバー画面を開きます。

```text
http://127.0.0.1:3001/driver
```

### 3. LINE用の公開入口を起動

別のターミナルで、受取人画面とWebhookに限定したプロキシを起動します。

```bash
node scripts/line-webhook-proxy.mjs
```

さらに別のターミナルでHTTPSの一時URLを発行します。

```bash
cloudflared tunnel --url http://127.0.0.1:3002
```

表示された `https://...trycloudflare.com` を `.env` の `LINE_PUBLIC_SITE_URL` に設定します。一時URLが変わった場合は、アプリとプロキシを再起動してください。

### 4. LINE Developersを設定

Messaging APIチャネルのWebhook URLへ次を設定します。

```text
https://<発行されたURL>/api/line/webhook
```

「Webhookの利用」をオンにし、「検証」が成功することを確認します。LINE公式アカウント側の既定の応答メッセージはオフにしてください。オンのままだと、システムの返信に加えて「個別のお問い合わせはできません」などの自動返信が届きます。

## リッチメニューの設定

レイアウトは上段を大きな1枠、下段を3分割にします。各領域のアクションタイプを「テキスト」にし、送信するテキストを次のとおり完全一致で設定してください。

| 配置       | 表示名     | 送信するテキスト |
| ---------- | ---------- | ---------------- |
| 上段       | 荷物の確認 | `荷物の確認`     |
| 下段・左   | 日時変更   | `日時変更`       |
| 下段・中央 | 再配達     | `再配達`         |
| 下段・右   | 使い方     | `使い方`         |

「日時変更」は初回配達前の荷物を対象とし、「再配達」は不在記録または再配達設定のある荷物だけを対象とします。在宅・10分不在・30分不在の操作は常設メニューには置かず、配達直前通知のクイックリプライにだけ表示します。

## 初回LINE連携

1. デモ用スマートフォンでLINE公式アカウントを友だち追加する
2. トーク画面で `初回連携 USER-C` と送信する
3. 「初回連携が完了しました」と返信されることを確認する
4. ドライバー画面で佐藤 健太さんの荷物 `YAMATO-0003` が「LINE連携済み」になったことを確認する

`USER-A`〜`USER-F` はダミーのお客様コードです。1つのLINEアカウントで複数の荷物を試す場合は、必要なコードでも初回連携を行います。

## 発表時のデモ進行（約3分）

### 事前状態

- ドライバー画面をPCで開く
- スマートフォンでLINE公式アカウントのトーク画面を開く
- 少なくとも1件をLINE連携済みにする
- 朝通知が未送信の状態にする。最も確実なのはデモ前に `pnpm exec supabase db reset` を行い、初回LINE連携をやり直す方法

### シーン1：当日朝

1. ドライバー画面で「朝8時の自動通知をデモ実行」を押す
2. スマートフォンに、お届け時間帯を含むLINE通知が届くことを見せる
3. 「配達状況を確認」を押し、LINE内ブラウザで到着目安・配送順・受取方法を見せる
4. LINEへ戻り、「今日は受け取れない」を押す
5. ドライバー画面に「本日は受取不可・日時変更待ち」が即時反映されることを見せる

説明例：

> 朝の時点で受け取れないと分かっている人を、訪問前に把握します。ドライバーが現地へ行ってから不在に気づく無駄を減らします。

### シーン2：配達直前

「今日は受け取れない」を押した荷物とは別のLINE連携済み荷物を使用します。

1. 対象荷物の「LINEで到着通知」を押す
2. LINEに表示された「あと何件・約何分」を見せる
3. 「10分不在」を押す
4. ドライバー画面に「短時間不在（○時○分まで）」が即時反映されることを見せる

説明例：

> 日付変更をするほどではない短い外出なら、10分だけ不在と伝えられます。ドライバーは訪問前に判断でき、同じ時間帯の中で無駄な不在訪問を避けられます。

## デモ後のリセット

全状態を初期化する場合：

```bash
pnpm exec supabase db reset
```

朝通知だけを再実行したい場合は、対象荷物の `morning_notification_sent_at` を `null` に戻します。通常は手作業による部分変更より、DB全体をリセットして初回連携をやり直す方が安全です。

## セキュリティ上の注意

- Cloudflareの一時トンネルで受取人画面を公開するのは、ダミーデータを使うデモ時だけにする
- 公開プロキシはドライバー画面を外部公開せず、Webhook・受取人画面・必要なAPIだけを許可する
- 受取人画面の公開URLは署名を検証し、36時間で失効する
- デモ終了後は `cloudflared` と `scripts/line-webhook-proxy.mjs` を `Ctrl+C` で停止する
- 本番では一時トンネルを使わず、AWS上のHTTPS環境、シークレット管理、利用者認証、監査ログを用意する

## トラブルシューティング

### LINE通知が0件になる

- LINE未連携
- すでに朝通知を送信済み
- 荷物が配達完了またはキャンセル済み

朝通知は二重送信を防止するため、同じ荷物へ繰り返し送信しません。

### Webhook検証は成功するが返信が来ない

- LINE Developersで「Webhookの利用」がオンか確認する
- `.env` の `LINE_CHANNEL_SECRET` を確認する
- アプリ、公開プロキシ、`cloudflared`の3つが起動中か確認する

### LINEから受取人画面が開けない

- `LINE_PUBLIC_SITE_URL` が現在の一時URLと一致しているか確認する
- 一時URLを変更した後にアプリを再起動したか確認する
- `EXPOSE_RECIPIENT_PAGES=true` か確認する
- 36時間以上前の通知は期限切れになるため、新しい通知を送る

### LINEから余分な自動返信が届く

LINE Official Account Managerで既定の応答メッセージをオフにします。
